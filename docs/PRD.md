# SHIT LAB 产品需求

状态：Phase 0 产品约定；本文中的第一版功能是后续开发目标，并非已实现功能。当前仅保留原始最小入口。变更范围以 [路线图](ROADMAP.md) 为准。

## 产品定位

SHIT LAB（思想实验室）是独立的实验性学术创作平台，用严肃清晰的表达容纳非传统论文、思想实验、奇特研究和独立观点。可以荒诞，但必须让读者分清事实、假设、模拟与虚构。平台不冒充正式学术期刊，不把发布当作同行评审或学术认可。

第一版采用静态网站：维护者在本地编辑文件，检查后构建并发布；读者通过浏览器直接阅读。没有在线投稿、数据库、账号或论坛后台。

## 目标用户与任务

| 用户 | 主要任务 | 产品应提供的帮助 |
| --- | --- | --- |
| 好奇的普通读者与大学生 | 找到感兴趣的研究并读懂论点 | 清晰标题、摘要、分类、正文与真实性标注 |
| 独立作者与创作者 | 表达非常规观点或展示可复现的小实验 | 可维护的论文文件格式、参考来源和修订记录 |
| 网站维护者 | 审核、增改和发布内容 | 文件化内容、明确构建步骤、可回退的 Git 历史 |
| 初学前端与 Linux 的开发者 | 理解并逐步维护网站 | 尽量少的技术栈、目录职责说明、分阶段验收 |

## 第一版范围与验收方向

| 能力 | 阶段 | 完成时应表现为 |
| --- | --- | --- |
| 品牌首页、基础导航、页面外壳 | Phase 1 | 桌面与手机可访问；键盘可用；不混入论坛交互 |
| 论文列表、详情、分类/标签与元信息 | Phase 2 | 内容来自独立文件；新增论文不复制布局代码 |
| 草稿控制、字段验证与真实性标签 | Phase 2 | 草稿不进入发布产物与列表；必填信息缺失时构建失败 |
| 本地静态搜索 | Phase 3 | 可查已发布论文；有空结果提示；不需要搜索服务器 |
| 数学公式、目录、引用、PDF 下载和长文阅读 | Phase 3 | 公式与代码可阅读；附件存在；手机不被长公式撑宽 |
| 质量验收、静态构建、受控发布与回退 | Phase 4 | 明确构建版本、链接无误、经授权再发布，可恢复旧版 |

PDF 优先支持作者提供的已审核文件；是否自动生成 PDF 留到 Phase 3 评估，不预先承诺复杂排版服务。文章正文是主要阅读入口，不能只留下 PDF 下载。

## 论文文件与真实性要求

正文计划存放于 `src/content/papers/`，优先 Markdown。文件前部的元数据称为 frontmatter，可理解为“文章信息表”；正文包含摘要/问题、假设、方法或推演、结果或讨论、限制、参考资料。思想实验不必伪造实验方法或数据章节。

Phase 2 再用内容集合落实以下字段；本阶段只规定契约，不创建 schema、样例论文或实际路由：

| 字段约定 | 目的与要求 |
| --- | --- |
| 稳定 ID / URL 标识 | 唯一、可读、避免随标题变更而断链；具体文件名映射在 Phase 2 决定 |
| 标题、摘要、作者、语言 | 便于读者判断主题；作者可用明确笔名，不伪造机构或资历 |
| 发布日期、修订日期、版本 | 日期使用明确日历日期；修订不得伪装成首次发布 |
| 分类与标签 | 有限且一致的词表，避免同义标签失控 |
| 发布状态 | 默认草稿，只有明确发布的文章进入构建产物；草稿不放入 `public/` |
| 内容类型 | 实证研究、模拟研究、思想实验、观点或虚构创作，至少明确一种主类型 |
| 数据/证据状态 | 真实观测、公开数据、模拟数据、无实测数据或尚未验证；可组合，但需逐项说明 |
| 来源、复现说明与限制 | 链接/文献、数据出处、生成过程、必要代码和局限；没有证据时如实说明 |
| 授权与附件 | 作者授权范围、第三方素材授权、可选 PDF 路径；不捏造 DOI、奖项或评审状态 |

真实性标签必须出现在摘要附近和正文需要澄清的位置；不能仅靠颜色表达。含真实与模拟材料的文章要分别标注图表和结论依据。图表注明数据来源、单位和处理方法；无法证实的数字不能写作已验证结果。

AI 辅助写作、图像或模拟材料应说明使用范围；作者仍对事实与引用负责。涉及真实个人的数据不得公开隐私。撤回、勘误与修订记录应保留可追溯说明，不悄悄改写旧结论。

## 非功能需求

- 可维护：Astro + TypeScript 严格配置 + 原生 CSS；文章、页面、布局和工具函数分开；直接依赖从实际需要出发。
- 可构建：锁文件进入 Git，生成的 `node_modules/`、`.astro/`、`dist/` 不提交。发布产物不依赖生产 Node 进程或数据库。
- 可阅读：中文长文优先；正文以系统字体为基础，窄屏可重排，支持键盘与浏览器缩放，遵循 [设计规范](DESIGN_SYSTEM.md)。
- 性能：默认静态 HTML，按功能逐步添加客户端脚本；不用 React 或大型状态管理承担简单界面任务。具体性能预算在 Phase 1/4 以实测建立，不虚构成绩。
- 安全与隐私：静态文件均视为公开；无实际凭证、环境值、服务器登录信息；本地仅回环监听；首版不引入第三方追踪。
- 可运维：未来只发布 `dist/`，发布前检查、保留上一版本、支持回退；生产操作必须另行授权。

## 明确暂不实现

第一版不包含用户注册/登录、个人主页、在线编辑/投稿、评论/论坛后台、支付、实时互动、数据库、后台管理、运行时 API 或跨服务单点登录。论坛在 Phase 5 作为独立项目规划；第一版只在架构文档中规定接入边界，不创建空后端。

Phase 0 不制作正式首页、组件、CSS、论文、搜索、公式或 PDF 功能；这些文件即使在目录中预留位置，也不代表功能已交付。
