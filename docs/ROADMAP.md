# 分阶段路线图

路线图描述后续工作，不构成提前开发授权。当前只执行 Phase 0；其实际完成情况见 [交接报告](reports/phase0-handoff.md)。每阶段结束都要记录变更、实际检查结果、风险与交接事项，并等用户给出下一阶段任务。

## 阶段、依赖与完成标准

| 阶段 | 任务 | 完成标准 | 进入条件 |
| --- | --- | --- | --- |
| Phase 0：治理与架构 | 只读盘点；保护历史文件与密钥；合并协作规则、README；建立目录与文档；检查 Git 和构建 | 盘点、交接齐全；可构建且可本地运行；无秘密进入候选文件；未越界开发、推送或部署 | 当前任务授权 |
| Phase 1：视觉体系与网页骨架 | 依据设计规范实现 CSS 变量、字体/网格；公共布局、导航、页脚；首页与基础页面骨架；替换示例品牌资源 | 有一致的黑白视觉；手机与桌面可用；键盘焦点清楚；不引入真实论文内容系统 | Phase 0 验收及用户新指令 |
| Phase 2：论文内容系统 | 确定字段/URL；Astro 7 构建期集合；列表/详情；分类标签；草稿筛选、证据状态及来源；少量经授权的内容 | 新增文章无需改布局；必填缺失/ID 冲突可发现；草稿不发布；列表与详情一致；真实性标注可见 | Phase 1 验收；可用的文章与授权信息 |
| Phase 3：阅读能力 | 静态搜索；公式与引用；目录/锚点；PDF 附件；长文、表格与代码在窄屏的体验 | 搜索覆盖已发布内容且有空结果；公式/目录可用；下载路径真实；长文可缩放、打印和键盘阅读 | Phase 2 稳定；搜索和 PDF 方案确认 |
| Phase 4：质量与阿里云部署 | 检查路由、附件、无障碍、移动端和性能；确定域名/base；构建版本；Ubuntu + Nginx 发布/回退；备案前受限测试 | 检查有实际证据；只有静态产物被发布；备份可回退；生产操作获授权；公开服务前完成相关备案要求 | Phase 3 验收；服务器/域名/备案与操作授权明确 |
| Phase 5：论坛独立规划与后续开发 | 单独需求与技术选型；独立服务/仓库/部署；评估治理、身份、数据、运维，再决定接入 | 首先产出可审阅方案；论坛故障不影响论文站；只有方案获准后才开发服务 | 第一版稳定；独立范围、运维能力与用户新授权 |

Phase 0 不创建 Phase 1 的 UI/CSS，也不实现后续内容 schema、搜索、PDF、API 或论坛服务。不能因为目录已存在就认定对应阶段已开始。

## 每阶段共同验收流程

1. 阅读上次交接与当前 Git 状态，确认本阶段范围及用户已有改动。
2. 更新相关需求/架构/设计文档，并在必要时增加一份小型 ADR。
3. 运行构建与已有检查；功能性页面增加对应实际路径/浏览器验证，不虚报未执行的检查。
4. 检查待提交文件、公开产物及敏感文件忽略规则，列出新增/修改/删除和保留疑问项。
5. 写阶段报告，中文解释决策与使用方法。是否本地提交由任务上下文决定；推送、生产变更与下一阶段需各自授权。

## 风险与待决策事项

| 事项 | 风险或影响 | 决策时间与处理 |
| --- | --- | --- |
| 本地 `master` 与远程 `main` 各有初始历史 | 直接 push 或盲目合并可能丢失远程说明/许可证，或产生 add/add 冲突 | Phase 0 给出基于远程 main 的整合分支方案；未经确认不执行整合/推送 |
| 工作区含历史页面及密钥 | 整体上传、清空或打印文件可能破坏既有环境 | 永久保护项目外文件；本阶段不删除任何文件 |
| 作者提供的数据和来源 | 奇特研究容易被误读为已验证事实 | Phase 2 落实证据标签、草稿控制与引用校验；不补造实验和结果 |
| 论文 URL、分类和授权 | 一旦发布后随意变化会断链或造成授权争议 | Phase 2 开始前确认稳定标识、词表与授权规则 |
| 中文字体与品牌语言 | 外部字体影响加载与隐私，巨大标题影响窄屏可读性 | Phase 1 以系统字体和可重排标题起步；确认中文为主及双语范围 |
| 搜索方案与资源预算 | 过早引入服务端搜索增加运维 | Phase 3 按实际文章数量比较本地索引方案；评估后才添加依赖 |
| PDF 提供/生成 | 自动排版可能引入浏览器与字体等重依赖 | Phase 3 优先审核后的作者附件；需要生成时另行选型 |
| 域名根路径或子路径 | 影响资源链接、canonical 和 Nginx 映射 | Phase 4 填写 `site`/必要的 `base`，在发布前统一验证 |
| 备案及生产授权 | 未备案公开访问可能被阻断；误操作影响旧站 | Phase 4 先受限测试，明确备份与恢复方案后再操作 |
| Node/npm 工具环境差异 | 同一机器的 Codex 与普通终端可使用不同版本 | 报告实际执行环境；使用已安装版本，不擅自升级或重装 |
| 论坛长期维护能力 | 数据、安全、审核与滥用处理超出静态站范围 | Phase 5 单独评估，首版不预建服务或共享会话 |
