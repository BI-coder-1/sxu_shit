# ADR-0001：静态论文网站与阶段边界

日期：2026-11-22。状态：采纳，依据本次用户给出的 Phase 0 范围。

## 背景

维护者具备 Python/C++ 基础，正在学习前端和 Linux。已有 Astro 7.4.13 项目可运行；工作区包含受保护的 SSH 文件与历史页面。本地、GitHub 分别初始化过仓库。第一版需要发表论文，不需要在线账号、数据库或论坛后台。

## 决策

1. 沿用现有 Astro + TypeScript 严格配置，后续使用原生 CSS；显式静态构建，开发/预览仅监听本机。
2. 文章、布局、页面和工具按目录分工。内容集合只在 Phase 2 落地，当前不实现空 schema 或示例论文。
3. 空目录由固定清单的本地脚本恢复，不用大量占位文件；不新增业务依赖。
4. 论坛以后独立仓库、独立部署，首先通过链接接入；当前只记录扩展原则，不创建后端、数据库或认证。
5. 远程 README 原文在本地说明中保留，LICENSE 保持原文。先检查历史，后续在远程 main 的整合分支中导入审阅后的文件；不强推或自动合并无关历史。
6. 本阶段只做治理、文档与最小运行保障。各阶段完成后报告并停止，路线图不代表后续授权。

## 结果与取舍

静态文件发布简单，运行时不依赖数据库或 Node 服务；内容有 Git 历史，适合小规模维护。代价是增改文章需要重新构建发布，不能直接提供在线投稿或即时讨论。

不选“现在就做全栈/论坛”的方案，因为它会引入当前没有需求的身份、数据和运维负担。不重建 Astro 或覆盖本地 Git，因为已有有效工程与历史；不为未来接口建立空服务，避免把计划误认成已实现功能。

## 重新评估条件

只有当独立服务已明确获得授权，或实际文章规模/协作方式证明静态流程不足时，再增加 ADR 评估变化。架构升级不能绕开文件保护、凭证规则与阶段边界。
